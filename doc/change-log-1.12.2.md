## Концепция сложности биомов

Сложность биомов и подземных зон в Minecraft (1.12.2) через графический интерфейс (HUD). Он определяет, находится ли игрок на поверхности (в биоме) или под землёй, и выводит соответствующую информацию:

- На поверхности – показывает название биома и его сложность в виде черепов.
- Под землёй – отображает уровень глубины и связанную с ним опасность.

**Примечания:**

- Красные черепа – обозначают сложность для скриптов (например, спавн мобов). Чем глубже – тем больше красных черепов.
- Оранжевые черепа – отражают сложность самого биома (например, враждебные биомы вроде джунглей или пустыни).

## Концпеция выпадения голов с сущностей

## Концепция улучшенного дропа вещей со скелетов

Реализована механика выпадения экипировки и стрел при смерти скелетов с учетом:

## Обновленная механика работы огня

- Добавляет эффект горения (1 сек) при смерти от огня, даже если моб не горел визуально (Работает только на серверной стороне)
- Делает 70% шанс что стрелы, выпущенные горящими скелетами, будут гореть (5 сек) (Не применяется к зомби и другим стрелкам)
- Автоматически тушит горящих существ с эффектом огнестойкости (Работает в реальном времени)
- Добавляет 30% шанс поджечь цель при атаке голыми руками горящим существом (2 сек)
- Особые правила для огнива:
- - Гарантированное поджигание на 3 секунды
- - Наносит 1 урон прочности огниву
- - Исключает зомби из механики огненных атак

- Все изменения происходят только на серверной стороне
- Учитывает сложность мира при расчете урона
- Использует простую вероятностную систему (tryPercentage)

## Обновленная механика работы факела

- Обрабатывает атаки мобов и игроков, держащих факел (Определяет тип атакующего (зомби/игрок/скелет))
- Если зомби атакует с факелом в руке → поджигает цель на 5 секунд
- Если игрок атакует с факелом в руке → поджигает цель на 5 секунд
- Если скелет атакует с факелом в руке → поджигает цель на 5 секунд
- Особый эффект при разрушении блоков факелом, при разрушении TNT факелом:
- - Создается мощный взрыв (сила 100)
- - TNT уничтожается без дропа
- - Факел превращается в палку (если не в креативе)
- - Отменяется стандартное разрушение блока

# [Игровое кеширование]

Система кеширования сущностей предназначена для эффективного отслеживания и управления мобами и другими живыми сущностями в мире Minecraft. Она состоит из трех основных компонентов:

1. CacheEntityStorage - хранит конфигурационные данные для различных типов сущностей
2. CacheFunctional - предоставляет функциональность для расчетов и операций с сущностями
3. CacheGeneralStorage - основной кеш, хранящий актуальные и буферные данные о сущностях

Основные компоненты:

**CacheEntityStorage**

Хранит конфигурацию для различных типов сущностей, включая:

- ResourceLocation - идентификатор сущности
- Флаги per_player и per_chunk - определяют, должен ли лимит сущностей масштабироваться в зависимости от количества игроков или чанков
- max_entity_count - максимальное количество сущностей данного типа
- result - результат обработки (используется для событий)

**CacheFunctional**

Содержит вспомогательные методы для работы с сущностями:

- Расчет максимального количества сущностей с учетом количества игроков и загруженных чанков
- Поиск ближайшего игрока
- Подсчет загруженных чанков в области видимости игрока
- Подсчет текущего количества сущностей определенного типа
- Определение валидных чанков для спавна относительно позиции игрока

**CacheGeneralStorage**

Основное хранилище кешированных данных, содержащее:

- Два набора данных (актуальный и буферный) для:
- - Животных (EntityAnimal)
- - Враждебных мобов (IAnimals)
- - Водных мобов (EntityWaterMob)
- - Всех живых сущностей (EntityLivingBase)
- - Мапы для быстрого поиска сущностей по имени и ResourceLocation
- - Набор валидных чанков (CACHE_VALID_CHUNKS)
- - Тайминги и счетчики для обновления кеша

**Принцип работы**

1. Инициализация:

- Каждый компонент инициализируется как синглтон через getInstance() и логирует свою инициализацию при наличии аннотации @InitLog.

2. Обновление кеша:

- Вызывается метод updateCache() в CacheGeneralStorage
- Очищается актуальный кеш
- Определяются валидные чанки для всех игроков
- Все загруженные сущности проверяются и добавляются в соответствующие коллекции

3. Двойное буферизирование:

- Данные хранятся в двух наборах - актуальном и буферном
- Метод copyActualToBuffer() копирует актуальные данные в буфер
- Это позволяет избежать проблем с параллельным доступом и обеспечить согласованность данных

4. Очистка кеша:

- Предусмотрены методы cleanActualCache() и cleanBufferCache() для очистки соответствующих наборов данных

5. Особенности работы:

- Масштабирование лимитов: При расчете максимального количества сущностей учитывается:
- Количество игроков (если per_player = true)
- Количество загруженных чанков (если per_chunk = true)
- Валидные чанки: Определяются на основе позиции игрока и расстояния обзора (viewDistance)
- Типы сущностей: Система различает животных, враждебных мобов, водных мобов и все живые сущности
- Поиск сущностей: Поддерживается поиск по имени и ResourceLocation

Система оптимизирована для многопоточной работы и минимизации нагрузки при частых запросах данных о сущностях.

# [Скриптовые парсеры]

**entity_cache_settings.json** - 

Парсер ожидает JSON-файл в следующем формате:

```json
[
  {
    "data": {
      "entity": "minecraft:zombie",
      "per_player": true,
      "per_chunk": false,
      "max_entity_count": 20,
      "result": "ALLOW"
    }
  },
  {
    "data": {
      "entity": "cow",
      "per_player": false,
      "per_chunk": true,
      "max_entity_count": 10,
      "result": "DENY"
    }
  }
]
```

**Ключевые параметры entity_cache_settings.json**

**entity** - Идентификатор сущности. Может быть указан в формате "мод:сущность" или просто "сущность" (в этом случае автоматически добавляется префикс "minecraft:").

Примеры:

- "minecraft:zombie"

- "twilightforest:deer"

- "cow" (будет преобразовано в "minecraft:cow")

**per_player** - Булево значение, определяющее нужно ли учитывать количество игроков при расчете лимита сущностей.

Допустимые значения: true или false.
При значении true максимальное количество сущностей будет масштабироваться в зависимости от количества игроков.

**per_chunk** - Булево значение, определяющее нужно ли учитывать количество загруженных чанков при расчете лимита сущностей.

Допустимые значения: true или false.
При значении true максимальное количество сущностей будет зависеть от количества загруженных чанков.

**max_entity_count** - Целое число, задающее максимальное количество сущностей данного типа.
Минимальное значение: 0 (полный запрет спавна сущности).
Чем выше значение, тем больше сущностей данного типа может существовать в мире.

**result** - Определяет результат обработки сущности. Допустимые значения:

- "ALLOW" - разрешить спавн (если условия соблюдены)
- "DENY" - запретить спавн (игнорируя другие проверки)
- "DEFAULT" - оставить решение на усмотрение других систем

Регистр значения не имеет ("allow" эквивалентно "ALLOW").
